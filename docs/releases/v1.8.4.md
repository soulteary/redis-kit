# redis-kit v1.8.4

## Changes

Update `github.com/redis/go-redis/v9` from **v9.23.0** to **v9.24.0**.
The minimum Go version is **1.27.4**.

The Redis client, cache, lock and rate-limit helpers use the updated client dependency.

This release contains no library source changes and does not change the public
API or module path.

## Redis client compatibility

Review the [upstream v9.24.0 release notes](https://github.com/redis/go-redis/releases/tag/v9.24.0)
when upgrading an application that uses Redis. In particular:

- Without a custom dialer, command retries no longer restart an already
  exhausted dial retry sequence for the same endpoint. Connection failures can
  therefore reach callers sooner.
- With `ContextTimeoutEnabled` enabled, socket timeouts caused by the caller's
  context deadline match `context.DeadlineExceeded` through `errors.Is`. The
  original transport error remains in the error chain, and these expired
  context operations are not retried.
- `MaxActiveConns` now accounts for all registered pool connections and
  in-flight dial reservations. Applications using this limit should review
  pool exhaustion handling under concurrent load.

## Upgrade

```sh
go get github.com/soulteary/redis-kit@v1.8.4
go mod tidy
```

Review the resulting dependency graph and run the application's Redis tests,
including its retry, timeout and pool settings.

## Rollback

Restore the application's previous `go.mod` and `go.sum`, then rebuild and run
its tests. Downgrading only redis-kit to v1.8.3 may leave go-redis v9.24.0
selected by another direct or indirect requirement through Go's minimal
version selection.
